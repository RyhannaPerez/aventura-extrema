# fase1. Analisis
documento analizo requerimientos funcionales y no funcionales

En esta primera fase nos enfocamos en entender bien de qué iba a tratar el 
proyecto y qué era lo que queríamos que hiciera.

Primero identificamos las necesidades del programa y anotamos los requisitos 
funcionales, es decir, las cosas que el programa debía poder hacer. También 
tomamos en cuenta los requisitos no funcionales, como que el programa fuera 
fácil de utilizar, estuviera bien organizado y funcionara correctamente.

También pensamos en qué información iba a ingresar el usuario, qué procesos 
iba a realizar el programa y qué resultados debía mostrar. Esto nos ayudó a 
tener una idea más clara antes de comenzar a programar.



# Fase2. Dise;o
diagrama de flujo

Después de tener claro lo que queríamos hacer, pasamos a la parte del diseño.

En esta fase realizamos un diagrama de flujo para representar de una manera 
más sencilla cómo iba a funcionar el programa. En el diagrama colocamos los 
diferentes pasos que debe seguir el sistema, incluyendo las decisiones y los 
resultados que se obtienen.

Hacer el diagrama nos ayudó a ordenar nuestras ideas y a entender mejor la 
lógica que posteriormente utilizaríamos para crear el código.


# fase3. Desarrolo
codigo en lenguaje de programacion en python

En esta fase empezamos a convertir todo lo que habíamos planeado en un 
programa real.

Utilizamos Python para escribir el código y desarrollar las funciones 
necesarias para que el proyecto pudiera funcionar. Durante este proceso 
fuimos probando el programa para comprobar que cada parte funcionara 
correctamente.

También tuvimos que revisar y corregir algunos errores que aparecieron 
mientras programábamos. Poco a poco fuimos mejorando el código hasta obtener 
el funcionamiento que buscábamos.
# fase4. Presentacion de github

Finalmente, organizamos nuestro proyecto para presentarlo en GitHub.

Subimos el código realizado en Python y agregamos el archivo README.md para 
explicar el proyecto y las diferentes fases por las que pasamos.

En el README explicamos qué hicimos durante el análisis, cómo diseñamos el 
programa, cómo lo desarrollamos y cómo organizamos el proyecto.

De esta manera, el repositorio quedó organizado y cualquier persona que lo 
consulte puede entender de qué trata el proyecto y conocer el proceso que 
seguimos para realizarlo.
